---
name: 诊断类提问只做解释,不擅自改文件
description: 用户问"为什么/什么原因"时通常只要原因解释和修复建议,明确说过"不修改文件"——先讲清楚,动手改之前要确认
type: feedback
---

当用户用"为什么 / 什么原因 / 帮我看下为什么"这类诊断式提问时,优先给出**原因分析 + 修复方案代码(贴出来即可)**,不要直接修改文件。

**Why:** 用户在某次提问("Unresolved dependency: common-util... 什么原因,不修改文件")中明确要求只解释原因、不修改文件;后续 Redis 不生效等提问也延续了"先讲清楚原因"的提问模式。

**How to apply:** 收到诊断类问题先定位根因并解释(引用具体文件:行号),给出修复代码块;想动手修改前先询问"需要我改吗",得到确认后再改。
